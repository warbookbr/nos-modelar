# Linha de base da porta de entrada dos agentes, 2026-11-05

O script `medir.py` conta o texto que as ferramentas devolveram a cada agente nas transcrições guardadas, por categoria (imagem, leitura de código do núcleo e das ferramentas, documentação, receita, execução de ferramenta) e por tipo de agente, e lista os arquivos de código mais lidos pelo modelador. Uso: `python3 docs/modelar/banco-de-provas/porta-de-entrada-2026-11-05/medir.py <diretório das transcrições do projeto>`, em que o diretório contém `<sessão>/subagents/agent-*.jsonl`. Imagem conta como 6000 caracteres estimados cada. A categoria de código soma os dois caminhos, o `Read` e o `grep`, `sed`, `cat` ou `head` do shell sobre `procedural/nucleo`, `src`, `tools` e `modulos`.

Números de 2026-11-05, com as 436 transcrições guardadas então, citados pelo plano: no modelador, 31% do texto recebido das ferramentas são imagens, cerca de 15% são leitura do código do núcleo e das ferramentas e 12% são documentação. O arquivo de código mais lido pelo modelador é `gaiola-por-estacoes.js`, com 477 KB somados, seguido de `descrever-peca.mjs` (315 KB), `vistas-de-passos.mjs` (202 KB), `executar-receita.js` (159 KB) e `guarda-acervo.mjs` (140 KB). A leitura dos quatro modeladores do braço mostrou que o da gaiola fez 26 chamadas e leu cerca de 112 mil caracteres, dois terços deles só para descobrir como se usa a gaiola.

Rodando o script de novo no mesmo dia, sobre 438 transcrições (179 do crítico visual, 123 do implementador, 99 do modelador, 36 de uso geral e 1 de exploração, 74,5 MB de texto no total), o modelador deu 25,9 MB, com 14,8% de código, 31,2% de imagens e 11,8% de documentação. Esse é o valor de comparação do gate de saída do plano: a leitura de código do modelador abaixo da metade de 15%, medida pelo mesmo script.
